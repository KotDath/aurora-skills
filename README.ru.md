# aurora-skills

Скиллы для разработки приложений под ОС Аврора и вспомогательный скилл для сообщений о проблемах с агентом.

> **Если ты AI-агент:** сначала прочитай [AGENTS.md](AGENTS.md) — там краткое описание проекта, скилл для выбора нужного набора и таблица доступных скиллов.

## Установка

### Через `npx skills`

Начните с интервью в каталоге проекта:

```bash
npx skills add KotDath/aurora-skills --skill setup-aurora-skills --copy
```

Интервью предложит подходящие скиллы, уточнит агента и локальную/глобальную область установки. Устанавливается только согласованный набор. Добавьте `--agent opencode` для OpenCode, `--global` для явно выбранной глобальной установки и сохраняйте `--copy`, чтобы устанавливать самостоятельные копии вместо симлинков. Рекомендуемый вариант — копии: удаление или изменение исходного checkout не должно ломать установленный скилл.

Для разработки устанавливайте `aurora-platform-context` вместе с выбранным development-скиллом. Полный набор остаётся отдельным вариантом, когда вы намеренно хотите все скиллы:

```bash
npx skills add KotDath/aurora-skills --agent opencode --skill '*' --copy
```

### Копированием файлов

Клонируйте репозиторий и копируйте **папку скилла целиком**, вместе с `scripts/`, `references/` и `assets/`, если они есть. Проектную `.agents/skills/` находят Codex, Pi, OMP и OpenCode.

```bash
git clone https://github.com/KotDath/aurora-skills.git
cd aurora-skills
PROJECT=/path/to/your/project
mkdir -p "$PROJECT/.agents/skills"

# Все скиллы:
cp -R skills/*/* "$PROJECT/.agents/skills/"
```

Чтобы скопировать только один скилл, замените последнюю команду на `cp -R skills/qt/aurora-qt-setup-project "$PROJECT/.agents/skills/"` (или укажите другую папку скилла из таблицы).

Чтобы скиллы были доступны во всех проектах, используйте вместо этого каталог `~/.agents/skills/`.

## Начните с интервью о проекте

Попросите агента использовать `setup-aurora-skills`, например: «Помоги настроить проект под Аврору. Расспроси меня о типе проекта и нужном SDK». Он сначала изучит существующий проект, затем спросит только о недостающих решениях: Qt/qmake, Qt/CMake, CMake + Conan, Flutter-приложение или Flutter-плагин с method channels, Qt либо FFI. Отдельно определит сценарий добавления Авроры в существующий проект или портирования плагина.

Setup сохраняет локальные SDK в исключённом из Git `.aurora/sdk.json`, добавляет краткий раздел о проекте в `AGENTS.md` (либо в существующий `CLAUDE.md`) и использует нужные установленные скиллы для запрошенного создания или сборки. Эти скиллы тоже должны быть установлены; интервью не устанавливает весь набор автоматически. Повторный запуск использует предыдущие ответы и меняет выбранные настройки без повторной генерации приложения.

Если нужный инструмент не найден в проверенных местах, setup предлагает указать существующий путь, установить его или продолжить с отложенной настройкой, когда это возможно. SDK и PSDK независимы: setup поддерживает SDK, PSDK или оба инструмента по выбранному сценарию. Для обоих отдельно учитываются версии, пути, проверки установки и незавершённые шаги; ожидание установки одного не блокирует работу со вторым. `aurora-install-sdk` проверяет Linux, спрашивает версию и BT/MB2, скачивает официальный установщик; пользователь проходит графическую установку, затем агент проверяет результат. `aurora-install-psdk` устанавливает PSDK только официальным скриптом и проверяет chroot, tooling и таргеты. Оба скилла работают и напрямую без интервью о проекте. Docker, когда он нужен выбранному процессу, только проверяется; устанавливает или исправляет его пользователь. Aurora Flutter fork эти скиллы не устанавливают.

CMake + Conan создаётся Qt-генератором в режиме `--build-system cmake --conan`: пустой рецепт, зафиксированная версия Aurora Conan и интеграция со сборкой и упаковкой RPM. Библиотеки автоматически не добавляются. Генерация платформенного каркаса Авроры для upstream Flutter-плагина сама по себе не завершает его портирование; оставшаяся работа отмечается отдельно. Любой специализированный скилл можно использовать напрямую без предварительного интервью.

## Знания о разработке хранятся в скиллах

Для работы над кодом выбирается `aurora-qt-development`, `aurora-flutter-app-development` или `aurora-flutter-plugin-development`. Каждый содержит практики своего стека и хорошие/плохие примеры в собственной `references/`. Вместе с ним устанавливается `aurora-platform-context`: общие правила источников, MCP и получения исходников эмбеддера хранятся только там. Интервью добавляет ссылку на выбранный скилл в `AGENTS.md`, не создавая дерево проектной документации.

Официальный MCP документации: `https://developer.auroraos.ru/api/mcp`. Скиллы сопоставляют официальную документацию нужной версии, заголовки выбранного SDK/PSDK и примеры с МосХаба. Для native-поведения Flutter можно скачать соответствующую SDK ревизию [Aurora Embedder](https://hub.mos.ru/auroraos/flutter/aurora-embedder); текущая основная ветка не доказывает поведение установленного SDK. Локальные версии скиллов имеют приоритет над глобальными, если пользователь явно не выбрал другую версию.

| [`aurora-flutter-setup-project`](skills/flutter/aurora-flutter-setup-project/SKILL.md) | Создать Aurora Flutter-приложение или плагин либо добавить поддержку Авроры в существующий проект. |
| [`aurora-flutter-add-dependency`](skills/flutter/aurora-flutter-add-dependency/SKILL.md) | Проверить зависимость по списку и добавить её через Aurora Flutter. |

| [`aurora-qt-development`](skills/qt/aurora-qt-development/SKILL.md) | Разрабатывать и ревьюить Qt/QML-код с практиками Авроры и проверкой источников по версии. |
| [`aurora-flutter-app-development`](skills/flutter/aurora-flutter-app-development/SKILL.md) | Разрабатывать и портировать Flutter-приложения с учётом совместимости и жизненного цикла Авроры. |
| [`aurora-flutter-plugin-development`](skills/flutter/aurora-flutter-plugin-development/SKILL.md) | Реализовывать и портировать Flutter-плагины через channels, Qt или FFI с проверкой исходников эмбеддера. |
| [`report-issue`](skills/util/report-issue/SKILL.md) | Собрать ZIP с описанием проблемы, текущей сессией агента и дочерними сессиями субагентов. |

[Список проверенных Flutter-зависимостей](skills/flutter/aurora-flutter-add-dependency/scripts/checked-dependencies.yaml) поддерживается вручную и лежит рядом со скриптом проверки. Он хранит исторические сведения. Допуск проверяется через `https://sdk-repo.omprussia.ru/sdk/flutter/pub/api/packages/<name>`; отсутствующие пакеты требуют проверки выбранной версии и зависимостей на отсутствие native-кода и `TargetPlatform`.

Сгенерированные проекты хранят локальные пути к SDK в исключённом из Git файле `.aurora/sdk.json`. Flutter setup записывает только явно выбранный Aurora Flutter SDK, не ищет и не вызывает sfdk. Qt setup может использовать `~/AuroraOS/bin/sfdk` как запасной путь.

Необязательное поле `psdk` хранит выбранный корень PSDK с `sdk-chroot`, а не внешний каталог установки. Оно независимо от `sfdk` и `flutter`: настройка одного инструмента не требует установки остальных. Скилл сборки Qt использует `sfdk`, а не PSDK.

Специализированные скиллы используют ответы из интервью и также работают напрямую. Сборка Qt, подпись и проверка RPM используют записанный `sfdk` исходного проекта, если пользователь не указал другой. Настройка рабочего процесса Flutter сохраняет SDK без генерации платформенных файлов. Для явной смены Flutter SDK скрипт setup поддерживает `--existing --record-only --replace-sdk --flutter-sdk <new-root>`; остальные настройки и файлы приложения сохраняются.

## Проверки при разработке

Команда `uv run --with 'PyYAML>=6,<7' python -m unittest discover -s tests -v` проверяет переходы Flutter setup, смену SDK, защиту каталога назначения, каркас Conan и ошибки его загрузчика. Можно также запустить `python3 -m unittest discover -s tests -v` в окружении с установленным PyYAML. Тесты используют локальные примеры и имитируют команды SDK и скачивания; установка SDK и доступ к сети не требуются. Подготовка Python-окружения может скачать PyYAML.
